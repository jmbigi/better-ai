## Objetivo

Convertir el análisis estático de `scripts/analyze_shell.py` (que detecta pipes
peligrosos como `curl ... | bash`, process substitution, eval/exec y
subcomandos destructivos encadenados) en enforcement real: ningún comando bash
que opencode vaya a ejecutar puede contener esos vectores, aunque el matcher de
permisos de `opencode.json` no pueda verlos (no matchea patrones con `|`,
limitación documentada).

## Criterios de aceptación

- `.opencode/plugins/guard-shell.js` implementa el hook `tool.execute.before`:
  para `input.tool === "bash"`, ejecuta `python3 scripts/analyze_shell.py` con el
  comando como argumento (nunca interpolado en un string de shell, para evitar
  inyección) desde el directorio de trabajo.
- Si el analizador reporta peligro (código de salida != 0), el plugin lanza un
  Error con la detección concreta, bloqueando la ejecución.
- Fail-closed (P1.19): si `python3` o el script no existen, o el análisis no
  puede completarse, el comando se bloquea con mensaje explícito. Sin fallbacks
  silenciosos.
- Comandos seguros (p. ej. `ls -la`) no se ven afectados.
- Alcance: opencode. Kilocode no tiene este sistema de plugins (verificación
  pendiente, documentada como limitación).

## Limitaciones

- El plugin solo aplica a opencode; kilocode carece de un sistema de plugins
  equivalente, por lo que allí el enforcement sigue dependiendo de los patrones
  deny de `kilo.json` (pendiente de verificación a fondo).
- `scripts/analyze_shell.py` no es un parser completo de Bash; construcciones
  muy retorcidas pueden escapar (limitación ya documentada en el propio script).
