## Objetivo

Portar el ruleset de guardarrailes a Kimi Code CLI (tercera herramienta
soportada, junto a opencode y kilocode) usando su configuracion declarativa
en TOML: reglas de permisos `[[permission.rules]]` en `.kimi-code/local.toml`
y un hook `PreToolUse` que ejecuta `scripts/analyze_shell.py` sobre cada
comando Bash propuesto por el agente.

## Criterios de aceptacion

- `.kimi-code/local.toml` contiene las reglas deny/ask/allow portadas de
  `opencode.json` con el orden invertido que exige el matcher
  primer-match-gana de Kimi Code: excepciones allow antes que los denies
  generales, denies antes que asks, y el catch-all allow al final (en
  opencode/kilo el allow comodin va primero porque usan last-match-wins).
- `.kimi-code/hooks/pre_bash_analyze.py` envuelve `scripts/analyze_shell.py`:
  lee el comando del JSON que Kimi Code pasa por stdin y bloquea con exit 2
  si el analisis estatico detecta patrones peligrosos (P0.8).
- La sintaxis TOML se valida con `tomllib` y el proyecto pasa
  `scripts/doc_validator.py --root .` y
  `bash scripts/verificar-proyecto.sh --pre-commit`.
- Las limitaciones (matcher sin verificacion empirica, posible no-carga de
  reglas desde `local.toml`, fail-open de hooks) se documentan en la
  cabecera de `.kimi-code/local.toml` y en `docs/INTEGRACION-ASISTENTES.md`.
